Geometry data, curated subsets, and model loading

TDF and CICY are geometry sources. KKLT is a curated index that stores conifold-class provenance, tags, and logical links back to TDF; it is not a separate geometry source.

Geometry data sources
cy-database / TDF Kreuzer-Skarke catalogues with sharded geometry, GV, polytope, and conifold data.
cy-database / CICY Complete-intersection catalogues with sharded geometry and derived model data.
Catalogue-convention I/O
CYDatabase Common query, cache, shard-loading, schema, and offline machinery.
TDFDatabase TDF rows addressed by ks_id and triang_id.
CICYDatabase CICY rows addressed by cicy_id.
Convention boundary: catalogue columns use source-geometry labels; LCSDatabase exposes mirror-convention h11 and h12.
Curated index and model bridge
LCSDatabase Builds lcs_tree data and ready-to-use FluxVacuaFinder models.
KKLTDatabase Advanced kklt index: conifold classes, logical TDF links, and tags.
Batch and sample APIs Load, iterate, and sample compatible models for scans.
Downstream use
JAXVacua Flux-vacua physics, periods, sampling, and stability analysis.
VacuaWriter Designated vacua with model identity and provenance.
Future consumers Kähler, axion, and optimisation workflows using the same data conventions.
